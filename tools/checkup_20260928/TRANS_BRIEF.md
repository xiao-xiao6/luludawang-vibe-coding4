# 翻译体检简报（pair_XX.txt → tverdicts/pair_XX.jsonl）

任务：逐条比对「原文」与「站内译文」，只查**错翻 / 少翻 / 漏翻 / 截断 / 加戏**，不改数据、不评价文笔。

## 文件格式（每题 5 行）
```
[lib_xxxxxxxx] 《标题》 来源=late-late.jp #1234（原文为日文|英文）
原文汤面: ...
站内汤面: ...
原文汤底: ...
站内汤底: ...
```
`late-late.jp` = 日本海龟汤站（日文原文）；`yesnogame.net` / `github:boop-yyt/situation_puzzle` / `Jed's List of Situation Puzzles (1999)` / `misc/repo-scan` = 英文原文。

## 只报这 5 类 kind
- **mistranslate**：意思译错（否定搞反、因果颠倒、人物关系错、关键名词张冠李戴、数字/时间错）。
- **omission**：原文里**属于这道汤**的内容被漏掉不译（如汤底最后的反转、关键一句没译）。
- **untranslated**：该译成中文的地方还留着整句日文/英文没译。
- **cut**：站内译文句中突然结束，而原文后面还有故事内容（被截断）。
- **addition**：站内凭空多出原文没有的情节或句子（不是措辞润色）。

## 不要报（很重要，避免误判）
1. 原文里的**源站脚手架不必翻译**，删掉是正确做法：BS 问题公告（`この問題はBS問題です…BSタイム…よろしくお願いいたします`）、出题人自己的留言/致谢（感谢各位参与、我是春雨/我是藤井、注册拉提新……）、`※图片来源`、URL、投稿说明、评论区贺词、大量颜文字与拟声词刷屏（`ドンドンパー`、`(°ﾛ °)ぱー`之类）、分节装饰线（`────`、`●○●○`、`◇◇◇`）。这些被删除或简写都算正确处理。
2. **站内比原文短很多是正常的**：中文比日文/英文紧凑，且第 1 条内容已被删。只有删掉的是故事本身才报 omission。
3. **本地化是正确的**，不要报：人名统一（カメオ→龟男、カメコ→龟女、ウミオ→海男、キョウコ→京子）、货币/量词换算、日期换算（平成→西元）、把外语谐音梗改成中文能懂的写法。
4. **刻意保留的日文假名/双关是正确的**：颜文字、`たな？`、`ふなよい＝2741`、五十音图题、なぞかけ（谜挂）等；数字串题（《熵增》）、化学式题（《给三兄弟的一封信》）保留原文符号也正确。
5. 语序调整、拆句合句、`「」`改`“”`、增删「的/了」等不影响意思的润色，一律不报。
6. 机翻腔、语句生硬但意思正确的，不报。

判定要**保守**：拿不准就不报，或在 note 写「待确认」。

## 输出
每个问题一行 JSON，字段：`id`（方括号里原样抄）、`kind`、`field`（surface/truth）、`note`（≤40 字中文，写清哪里错、原文说什么）、`orig`（原文关键片段 ≤50 字）、`site`（站内对应片段 ≤50 字）。
- 一行一个 JSON，不要数组包裹、不要注释、不要 markdown 代码块。
- 整批无问题则写一行 `{"id":"NONE","kind":"none","note":"整批无问题"}`。
- 必须**逐条读完全批**（文件大，用 Read 的 offset/limit 分多次读到结尾），不要抽样跳读。
- 结束用一句话汇报：审了多少题、五类各多少。
