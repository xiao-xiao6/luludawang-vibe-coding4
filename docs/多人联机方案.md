## 二、架构说明（A1 的代价，已接受）

- 单人 + 多人全部走服务端 → **离线不可玩**，PWA 退化为「离线只能翻汤库」
- 公开网址带来的 token 消耗风险 → 阶段 6 加**按 IP 日调用上限**（单人限流，多人房不设限）
- 汤底必须搬服务端：现在 `data.js` / `library.data.js` 把 `truth` 全塞前端，F12 可直接通关
- `engine.js` 为纯逻辑（不碰 DOM），可整段搬进 Worker
- `_proxy/` 本地 CORS 桥在 A1 后可退休

## 三、施工阶段

### ✅ 阶段 0：修 2 个 AI 体验 Bug（纯前端，最快见效）

**病灶 A —— 重复提问被拦**（`js/app.js:712`）
```js
if (state.asked[key]) { ...return; }
state.asked[key] = 1;   // ← 在 AI 返回之前就记账了
```
根因：AI 请求是异步的，`state.asked` 在发起时就记账 → AI 掉线回退后，同一问题再也问不了。
**修法**：改为 **AI 成功返回才记账**；AI 失败**回滚记账**，允许重问。

**病灶 B —— 猜底秒出关键词回复**（`js/app.js:1162~1172`）
```js
var j = E.judgeGuess(p, text);   // 同步，秒出
if (aiOn()) {
  book(j.level, j.note);          // ← 直接上屏，玩家误以为是 AI 的答复
  AI.judgeGuess(p, text).then(...) // AI 回来才覆盖
```
根因：关键词结果同步、AI 结果异步，同步"底线"被当成正式答复外显。
**修法**：AI 模式下**只显示「AI 汤主正在判断你的推理…」**；关键词判定**彻底降级为内部兜底，永不上屏**。

**病灶 C —— AI 掉线文案统一**
- 提问失败：`AI 汤主掉线了，请重新提问一次`
- 推理失败：`AI 汤主掉线了，请重新提交推理`
- 三条铁律：**不记问答历史、不计入已问、不消耗回合**

### ✅ 阶段 1：砍跨局存档（纯前端）

删除：`progress.puzzles[].solved / stars / bestQ / bestHints`、`records`、`recent`、`daily`、`randUnsolved`、`#count-solved` 徽章、星级显示。
保留：`state.asked / revealed / hintsUsed`（局内）、`saveSession()`、`btn-resume`（继续上一锅）、`sound / music / fx / volume`（偏好）。

### ✅ 阶段 2：左侧改问答区 + 汤库入口（纯前端）

- `#log` 区域语义从"汤单"改为**滚动问答历史**（单人/多人统一）
- 顶部新增 `📚 汤库` 按钮，作为汤单与 1361 道库题的**唯一入口**

### ⏳ 阶段 3：身份 & 昵称
- 客户端生成 `internalId`，进项目弹昵称框（可重复、必填、≤12 字）
- 服务端分配 UID（房主固定 `#1`）

### ⏳ 阶段 4：房间 + 同步（后端主力）
- 后端：一个房间 = 一个 Durable Object
- 第一版 **HTTP 轮询**（1~2s，海龟汤节奏无感）
- 建房 / 房号 / 进房 / 准备 / 随机顺序 → `phase: playing`

### ⏳ 阶段 5：双通道游戏逻辑
- 提问通道：仅 `players[turnIdx]` 可问，服务端判定 → 追加 `qaLog` → 轮转；60s 超时跳过
- 猜底通道：随时可猜，服务端判定 → 红 180s / 黄 60s / 绿结束

### ⏳ 阶段 6：AI 服务端化
- 汤底搬服务端；判定逻辑搬 Worker；AI key 只存服务端
- AI 掉线：提示重问，不记账不消耗回合
- 加按 IP 日调用上限（防公开网址被刷）

## 四、验收铁律

1. 每阶段**独立可验收、独立可回滚**
2. 阶段 0~2 不碰网络，随时可退
3. 每阶段结束跑现有自检断言，**不合格不往下走**
